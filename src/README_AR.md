# firmware المتحكم — `main.cpp`

يحتوي هذا المجلد **ملف C++ واحدًا فقط**. يختار المترجم فرع Uno أو ESP32 عبر تعريفات اللوحة وتعريف الدور المضاف من `platformio.ini`؛ لا يحتاج المستخدم إلى نسخ ملفات firmware منفصلة.

## بيئات البناء

| الأمر | اللوحة | الدور |
|---|---|---|
| `pio run -e uno` | Arduino Uno R3 / ATmega328P | قيادة المحركات والحساسات والبازر على Uno. |
| `pio run -e esp32_bridge` | ESP32 Dev Module `esp32dev` | Bluetooth Classic SPP ↔ UART2 ↔ Uno؛ يستقبل الأوامر ويمررها فقط، ولا يقود المحركات بنفسه. |
| `pio run -e esp32_standalone` | ESP32 Dev Module `esp32dev` | firmware كامل على ESP32 بعد نقل الأسلاك إليه. |

الهدف ESP32 هو اللوحة الأصلية ذات وحدة ESP32-WROOM-32 الداعمة لـBluetooth Classic SPP؛ لا يفترض أن يعمل على ESP32-S3/C3 أو أي pinout آخر دون تعديل وفحص.

## أقسام المصدر

1. تعريف اللوحة والأرجل والثوابت.
2. قراءة MPU6050 التقديرية.
3. HC‑SR04 ومدخل IR.
4. L298N، اتجاهات المحركات، ومخارج PWM.
5. Serial وBluetooth والجسر وwatchdog.
6. أنماط البازر وقراءة المقاومة المتغيرة.
7. بروتوكول الأوامر والسرعة وحواجز الحركة.
8. مؤشرات LED.
9. التهيئة والحلقة الرئيسية.

## نقاط يجب معرفتها

- اتجاه الموتورين يعكسه الثابتان `REVERSE_LEFT_MOTOR` و`REVERSE_RIGHT_MOTOR`؛ اختبرهما والعجلات مرفوعة.
- مستوى PWM لا يقيس RPM. إزالة جسري ENA/ENB وتغذية L298N الصحيحة شرط ظهور فرق فعلي.
- `TURN_45_DURATION_MS` يساوي 200ms مبدئيًا، ولا يضمن 45° قبل المعايرة.
- `Z` heartbeat يسلح إيقافًا تلقائيًا بعد نحو 350ms من انقطاع الجسر.
- Uno يستخدم Timer1 على D9 لإخراج نغمات بدورة عمل متغيرة؛ مكتبة Servo قد تتعارض مع Timer1.
- الحماية الأمامية محدودة ولا تمنع الاصطدام في كل الاتجاهات.
- في الوضع الهجين تبقى الحساسات والمحركات والبازر والـLEDات على Uno؛ وضع المفتاح يختار مسار الأوامر ولا ينقل المكونات أو يرفع firmware تلقائيًا.
- R2 منفردًا يطلب `F`، وL2 منفردًا `B`؛ ومع Y يصبحان دورانًا في المكان. راجع خريطة التحكم لتفاصيل الأولوية.
