# مشروع حركة الروبوت والتنبيه الصوتي

مستودع تعليمي لروبوت صغير يتحرك بتحكم يدوي من الكمبيوتر. يقرأ برنامج Python ذراع التحكم، ويرسل أوامر قصيرة عبر USB Serial إلى **Arduino Uno R3**. يتولى الأردوينو قيادة محركين من خلال L298N، وقياس مسافة أمامية بصورة محدودة، وتشغيل بازر عند طلب النغمات.

> **تنبيه سلامة:** هذه نسخة تجريبية وليست نظامًا يمنع الاصطدام بصورة مضمونة. حساس HC‑SR04 يوقف أوامر أمامية محددة عند قراءة أقل من 15 سم، لكن غياب Echo يُفسَّر حاليًا كأن الطريق خالٍ. لا يوجد مؤقت توقف مضمون عند انقطاع الاتصال، ولا يوجد اتزان ذاتي PID. ابدأ والعجلات مرفوعة، وافصل طاقة المحركات أثناء التوصيل، وأبقِ مفتاح فصل الطاقة في متناولك.

## ما الذي تنفذه النسخة الحالية؟

- تحكم يدوي في محركين عبر Arduino Uno وL298N.
- جسر Python يقرأ ذراع التحكم باستخدام pygame، ويرسل حرفًا واحدًا عبر USB Serial بسرعة **9600 baud**.
- تشغيل بازر سلبي موصول على A0: زمارة `H` وأربعة أنماط نغمية مرقمة `1` إلى `4`.
- قياس أمامي باستخدام HC‑SR04؛ حد التوقف الحالي يعمل فقط مع الأوامر `F` و`J` و`^` عندما تكون القراءة أقل من 15 سم.
- قراءة MPU6050 مبسطة تُستخدم في حركتين قصيرتين مرتبطتين بعتبة ميل. هذه القراءة ليست تقديرًا معايرًا للزاوية ولا حلقة اتزان.
- رجل مستقبل IR مضبوطة كمدخل فقط؛ لا يوجد فك لإشارة الريموت أو ربط لأزراره.

لا يَعِد المشروع بتجنب جميع العوائق. راجع القيود بالتفصيل في [وثيقة السلامة](docs/SAFETY_AND_TESTING.md).

## البناء والتشغيل

### بناء برنامج Arduino Uno

ثبّت [PlatformIO Core](https://docs.platformio.org/en/latest/core/index.html) أو إضافة PlatformIO في VS Code. من مجلد المستودع نفّذ:

```bash
pio run -e uno
pio run -e uno -t upload
pio device monitor -e uno
```

إعداد المنفذ التسلسلي هو 9600 baud. أغلق Serial Monitor قبل فتح المنفذ نفسه من جسر Python.

### تثبيت جسر ذراع التحكم

يتطلب الجسر Python 3.10 أو أحدث. على Linux أو macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r scripts/requirements.txt
python scripts/bridge.py --list-ports
python scripts/bridge.py --list-controllers
python scripts/bridge.py --self-test
python scripts/bridge.py --port /dev/ttyACM0
```

على Windows PowerShell فعّل البيئة بالأمر `.venv\Scripts\Activate.ps1`، ثم استخدم المنفذ الذي يظهر لديك، مثل `COM3`:

```powershell
python scripts/bridge.py --port COM3
```

تختلف أرقام أزرار ومحاور أذرع التحكم بين الأجهزة. استخدم `--list-controllers` أولًا، ثم راجع [شرح الجسر](scripts/README_AR.md) و[جدول الأوامر](docs/CONTROLLER_MAPPING.md).

## مراجعة أرشيف `Buzzer_Music.zip`

ملف `src/main.cpp` داخل الأرشيف يطابق البرنامج الموجود هنا بعد تجاهل اختلاف المسافات البيضاء؛ لذلك لم نستبدل كودًا أو نعدّله. ملف `bridge.py` داخل الأرشيف نسخة أقدم تثبّت منفذًا بعينه وترسل أوامر بصورة متكررة، لذلك بقي الجسر المنظم الموجود في `scripts/`. لم تُنقل مجلدات `.pio` و`.vscode` ولا نسخ المكتبات غير المستخدمة. كذلك لم نضف مخطط المحاكاة: فهو يوصل البازر إلى D7، بينما البرنامج يعرّف البازر على A0.

## ملاحظات قبل اعتبار الروبوت جاهزًا

- مهلة حساس HC‑SR04 تعطي 999 سم عند غياب Echo؛ قد يؤدي ذلك إلى عدم اكتشاف العائق.
- التوقف الأمامي لا يغطي الرجوع أو الدوران أو كل أوامر الحركة.
- توجد استدعاءات `delay()` تعطل استقبال أوامر جديدة مؤقتًا.
- آخر أمر يظل محفوظًا في البرنامج إذا انقطع الاتصال؛ إرسال `S` من الكمبيوتر أفضل جهد وليس ضمانًا.
- مسار ESP32 داخل المصدر غير مهيأ أو مختبر كبيئة بناء مستقلة، وخريطة الأرجل هنا خاصة بـUno.
- لم يُختبر عتاد فعلي ضمن هذا التحديث. نجاح البناء لا يثبت سلامة التوصيلات أو مسافة التوقف.
