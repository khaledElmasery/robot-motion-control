# مقارنة النسخة الحالية بأرشيف `Buzzer_Music.zip`

قورنت ملفات الأرشيف المرفق مع بنية المشروع الحالية. النسخة الحالية ليست نسخًا حرفيًا للأرشيف القديم: الهدف مشروع محدث ومتسق مع `main.cpp` و`bridge.py` الموحدين، لذلك أُبقيت الملفات اللازمة للبناء والتشغيل والتوثيق، ولم تُنسخ ملفات قديمة أو مولدة لمجرد زيادة العدد.

## ما تم تحديثه أو استبداله

| الأصل في الأرشيف | وضعه في المشروع الحالي | السبب |
|---|---|---|
| `src/main.cpp` | استُبدل بمصدر موحد في `src/main.cpp` الحالي | القديم Uno-only وخريطته لا تطابق أرجل الصوت/PWM الجديدة ولا أدوار ESP32 الثلاثة. |
| `bridge.py` في جذر الأرشيف | استُبدل بالملف `bridge.py` داخل `scripts/` | الجسر الحالي موحد للسلكي وBluetooth SPP ويتضمن فحص الفهارس وheartbeat وخريطة الأزرار الحديثة. |
| `platformio.ini` | أُعيد تنظيمه بثلاث بيئات | الإعداد القديم كان خاصًا ببناء Uno فقط. |
| `.gitignore` | يوجد في جذر المشروع | يستثني مخرجات البناء والكاش والبيئات المحلية. |
| `.vscode/c_cpp_properties.json` وملفات جلسة VS Code | لم تُنسخ إعداداتها الخاصة بالجهاز؛ توجد توصية إضافة PlatformIO عامة في `.vscode/extensions.json` | مسارات IntelliSense القديمة مرتبطة بجهاز وبيئة بعينهما وقد تعرض أخطاء `Wire.h` حتى عندما يكون بناء PlatformIO سليمًا. |

## عناصر أرشيفية مستبعدة عمدًا

- مجلد `.pio/` يتضمن مخرجات بناء ونسخًا محمّلة من مكتبات؛ لا يُحفظ عادةً داخل مشروع مصدر، ويعاد توليده بواسطة PlatformIO.
- مجلدات `lib/` و`.pio/libdeps/` تتضمن نسخًا مكررة من I2Cdev/MPU6050/PID وLMotorController. المصدر الحالي لا يستوردها؛ يستخدم Arduino `Wire` ويدير الموتورات والقراءة مباشرةً. إضافتها الآن ستزيد نسخ المكتبات وتراخيصها من دون أن يحتاجها البناء الحالي.
- `include/README` و`lib/README` و`test/README` ملفات تمهيدية/عامة وليست وحدات مستخدمة في البرنامج الحالي. صار شرح المشروع في `README.md` والوثائق العربية واختبارات Python في `tests/`.
- `diagram.json` القديم يحوي Arduino Uno وبازرًا واحدًا على الطرف المطبوع `7` فقط، بينما firmware الحالي خصص البازر إلى الطرف المطبوع `~9` وأعاد ترتيب ENA/ENB وأضاف حساسات وأوضاع ESP32. لذلك وضع الرسم القديم داخل الحزمة على أنه مخطط صالح سيضلل المستخدم.
- `wokwi.toml` القديم يشير إلى ملف ELF الناتج من بيئة Uno، لكنه لا يوفر محاكاة كاملة للمحركات والحساسات والـESP32. لم يُدرج باعتباره محاكاة صالحة للنسخة الجديدة.
- ملفات تاريخية مثل `.pio` ليست “كودًا ناقصًا”؛ هي أدوات/مخرجات أو مكتبات قديمة غير مستوردة إلى الإصدار الحالي. إذا تقرر لاحقًا استخدام Wokwi، يلزم إنشاء رسم جديد مطابق للأرجل الحالية واختباره مستقلًا.

## هل يلزم تنزيل مكتبات خارجية؟

بحسب ملفات المصدر الحالية، لا يحتاج بناء Uno إلى مجلدات المكتبات المكررة من الأرشيف. يتولى PlatformIO تثبيت منصة اللوحة وArduino framework؛ ويستعمل البرنامج `Arduino.h` و`Wire.h` من الإطار. يعتمد جسر Python على الإصدارات المثبتة في `scripts/requirements.txt`.

## ما ينبغي فتحه في VS Code

فك ضغط الحزمة في مجلد جديد، ثم افتح المجلد الذي يحتوي مباشرةً على `platformio.ini` و`README.md` و`src/`. لا تفتح مجلدًا أبًا يحتوي نسخة أخرى متداخلة. يوصى بتثبيت إضافة **PlatformIO IDE**؛ رسائل `cannot open source file "Wire.h"` من IntelliSense وحده ليست حكمًا نهائيًا على البناء، بينما نتيجة `pio run` هي فحص البناء الفعلي.
