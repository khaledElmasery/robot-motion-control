# السلامة والاختبار

## حالة المشروع

هذا نموذج تجريبي للتحكم بمحركات، وليس روبوتًا معتمدًا للسلامة أو نظامًا مضمونًا لمنع الاصطدام. يوجد watchdog لنبضات جسر Python وقفل أمامي محدود يعتمد على HC‑SR04؛ لا يحمي كل الاتجاهات ولا يضمن منع الاصطدام. لم تُختبر اللوحات أو الأسلاك أو المحركات فعليًا ضمن هذا التحديث.

## تحذيرات كهربائية وميكانيكية

1. محركات Yellow TT مصنفة 3–6V. بطارية 3S من خلايا 18650 تعطي 11.1V اسميًا وتصل 12.6V كاملة الشحن؛ **لا توصلها مباشرة بالمحركات أو مدخل المحرك في L298N**. استخدم Fuse وBuck مضبوطًا على 5–6V كحد أقصى مع تيار بدء/تعثر كافٍ. مصدر 5V المنظم للمنطق يجب ألا يُوصل بالتوازي مع مصدر 5V آخر أو USB بطريقة قد تسبب رجوع تيار.
2. مكثف 100µF/25V يوصل مع مراعاة القطبية: الموجب إلى خط VBAT بعد المفتاح، والسالب المخطط إلى GND. لا يكفي وحده لإزالة كل تشويش المحركات؛ اتبع أيضًا توصيات وحدة L298N لمكثفات الفصل القريبة.
3. **الدايودات مهمة:** شريحة L298 ذات الجسرين تحتاج أربعة دايودات سريعة لكل جسر إن لم تكن مدمجة بالوحدة. الأربع 1N4007 المذكورة ليست حماية كاملة لمحركين، وورقة ST تطلب عناصر سريعة الاستعادة/تفضل Schottky. افحص الوحدة لتتأكد من وجود ثمانية دايودات مدمجة؛ إن لم توجد، لا تشغّل المحركات قبل تركيب النوع والعدد المناسبين وفق ورقة L298.
4. أزل جسري `ENA` و`ENB` على لوحة L298N كي يعمل PWM، لكن تحقّق من جسر منظم `5V` وطريقة تغذية المنطق الخاصة بوحدتك؛ تختلف الوحدات الفرعية ويؤدي التوصيل الخاطئ إلى تلف اللوحة.
5. مفتاح SPST الخاص بتغذية ESP32 لا يعزل UART. قد يرجع جهد Uno `TX→1` إلى ESP32 وهو مطفأ عبر حماية الرجل. في وضع Uno المباشر يجب فصل سلكي UART؛ والأفضل استخدام مفتاح وضع متعدد الأقطاب يفصل UART وتغذية ESP32 معًا. لا توصل كابل USB data إلى Uno أثناء الهجين لأن `RX←0` و`TX→1` مشتركان مع محول USB-Serial على اللوحة. افصل UART كذلك قبل برمجة Uno أو فتح Serial Monitor.
6. لا توصل Echo ذي 5V مباشرة إلى ESP32. استخدم مقسم 1kΩ/2kΩ كما في [دليل التوصيلات](WIRING_AND_HARDWARE.md). GPIO في ESP32 يعمل بمنطق 3.3V ولا يتحمل 5V.
7. خريطة ESP32 هنا مخصصة للوحة ESP32-WROOM-32 الأصلية من فئة `esp32dev`. إذا كانت لوحتك S3/C3/WROVER أو اختلفت تسميات الأرجل، لا توصلها على هذا الأساس.
8. لا توصل/تفصل محركًا أو سلكًا والبطارية متصلة. استخدم BMS وشاحنًا مخصصًا لحزمة 3S، وفيوزًا وأسلاكًا مناسبة لتيار التعثر. لا تشحن الحزمة عبر Arduino ولا تتركها دون مراقبة.
9. ابدأ والعجلات مرفوعة على منضدة ثابتة، وافصل تغذية المحركات أثناء الأسلاك، وأبقِ مفتاح فصل الطاقة في يد المشغّل. أبعد اليدين والملابس والأشياء عن العجلات والتروس.

## القيود المعروفة في البرنامج

- أوامر `F/J/^` تتوقف إذا فشل Echo أو كانت المسافة أقل من 15cm؛ لا يشمل ذلك `B/L/R/C/c/< />`، لذلك يلزم إشراف مباشر ومساحة خالية.
- `pulseIn()` قد ينتظر حتى 25ms، وهناك تأخير قصير في الحلقة؛ ليس هذا ضمانًا لاستجابة فورية.
- Python يرسل `Z` كل 100ms. بعد نحو 350ms بلا نبضة يتوقف البرنامج ويُلغى الأمر المؤقت. عند استخدام Serial Monitor مباشرة لا يُسلّح watchdog إلا إذا أرسلت `Z`.
- درجات PWM مفتوحة الحلقة. لا توجد مشفرات عجلات لقياس RPM أو حلقة تصحيح. قد لا يبدأ المحرك عند القيم المنخفضة، وقد تختلف المحركات.
- الأمران `<` و`>` مدتهما 200ms افتراضيًا ولا يضمنان زاوية 45°. يلزم معايرة على الهيكل الحقيقي.
- أوامر `^` و`V` تشترط قراءة ميل تقريبية من MPU6050؛ لا يوجد PID أو دمج جيروسكوب أو اتزان.
- تحكم البازر بالديسيبل غير معاير. Uno يستخدم Timer1 على `~9`، فلا تستخدم Servo أو مكتبة أخرى تعتمد Timer1 دون تغيير التصميم.
- مستقبل IR لا يفك أي بروتوكول. اتصال ESP32 اللاسلكي Bluetooth Classic SPP فقط؛ Wi‑Fi/TCP غير منفذ.

## فحوص برمجية بلا عتاد

من جذر المشروع:

```bash
pio run -e uno
pio run -e esp32_bridge
pio run -e esp32_standalone
python3 -m py_compile scripts/bridge.py tests/test_bridge.py
python scripts/bridge.py --self-test
python -m unittest discover -s tests -v
```

الترجمة والاختبارات لا تبرمج لوحة ولا تثبت سلامة الأسلاك أو التشغيل. لا تستخدم `-t upload` قبل تحديد اللوحة والمنفذ وفصل تغذية المحركات.

## تسلسل اختبار يدوي محافظ

1. حدّد طراز اللوحة المكتوب على وحدة ESP32. إذا لم تكن ESP32-WROOM-32 الأصلية، لا تستخدم جدول أرجل ESP32 الحالي.
2. افصل البطارية. طابق كل طرف حسب [جدول التوصيلات](WIRING_AND_HARDWARE.md). افحص Buck والمقسمات والأرضي والجهود وجسري ENA/ENB والدايودات على وحدة L298N.
3. قِس خرج Buck للمحركات وتأكد أنه لا يتجاوز 6V قبل وصله بـL298N. تحقق من قطبية مكثف 100µF/25V ومن قيمة خرج Buck للمنطق.
4. في وضع Uno فقط، نفّذ `pio run -e uno`. افتح Serial Monitor بسرعة 9600، وأرسل `S` ثم `F` مع Enter والعجلات مرفوعة. يتجاهل البرنامج CR/LF ويمنع التقدم إذا كانت قراءة Echo غير صالحة.
5. والعجلات مرفوعة، اختبر كل اتجاه لفترة قصيرة. اختبر `+` و`-` وتأكد من رسائل `SPEED_LEVEL=n PWM=p` ومن اختلاف PWM على ENA/ENB. أوقف فورًا إذا انعكس اتجاه متوقع أو سخن السلك/الدرايفر.
6. والمحركات مفصولة، اختبر HC‑SR04 بعائق قريب (<15cm) ثم غياب Echo؛ يجب أن يحجب `F/J/^`. لا تعتمد عليه لحماية الحركات الأخرى.
7. افحص يد التحكم دون فتح منفذ Serial:

   ```bash
   python scripts/bridge.py --probe-controllers
   ```

   حرّك كل عصا واضغط كل زر منفردًا، خصوصًا A/X وY/R2/L2 وL1/R1 وR3 وD-pad. عدّل الفهارس حسب الفحص لا حسب الافتراض.
8. أغلق Serial Monitor. شغّل الجسر والعجلات مرفوعة. اختبر Space، وفقدان تركيز النافذة، وانقطاع يد التحكم، وفصل Bluetooth/USB، وتأكد من توقف watchdog. أبقِ مفتاح الطاقة في متناولك.
9. اختبر البازر والمقاومة المتغيرة دون تغذية المحركات. تحقق من نوع البازر وحد تيار GPIO؛ أضف Driver إذا لزم.
10. لا تختبر قرب أشخاص أو حيوانات أو ممتلكات قابلة للكسر أو سلالم أو طريق عام، ولا تترك الروبوت يعمل دون مشغّل.

## وصف دقيق للمشروع

يمكن وصف النسخة بأنها **تحكم يدوي ثنائي المحرك بمستويات PWM مفتوحة الحلقة، وأنماط صوتية، وقفل تقدم محدود، وwatchdog عند استخدام جسر Python**. لا تصفها بأنها ذاتية الاتزان أو مضمونة منع الاصطدام أو ذات سرعة/زاوية دقيقة أو آمنة دون إشراف.
