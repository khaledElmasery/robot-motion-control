# اختبار جميع أزرار ريموت SUPER GOLD X3 / SG-555

هذه نسخة اختبار جاهزة بخريطة الأزرار التي تعلّمها Arduino من **ضغطاتك الفعلية على الأزرار الـ45**. عند الضغط على زر، يطبع Serial اسمه مثل `POWER` أو `UP` أو `DIGIT_1`. لا تحتاج إلى إعادة المعايرة كي تختبرها.

**المنافذ مضبوطة على `COM8`، وسرعة Serial هي `115200`.** برنامج الاختبار يستقبل IR ويطبع فقط؛ لا يشغّل المحركات ولا يرسل أوامر حركة. حتى زر `POWER` يطبع الاسم فقط ولا يشغّل الروبوت أو يطفئه.

## ابدأ من هنا

1. عند تنزيل الحزمة وحدها، افتح المجلد **`ir-remote-verification-kit`**؛ وإذا فتحت مستودع المشروع كاملًا، افتح `tools/ir-remote-verification-kit` داخل VS Code عن طريق **File → Open Folder**. لا تفتح `src/main.cpp` وحده.
2. وافق على **Trust** إذا ظهر تنبيه Workspace Trust، وثبّت إضافة **PlatformIO IDE** إذا لم تكن مثبتة. انتظر حتى تجهّز الإضافة المشروع ومكتبة `IRremote`.
3. صِل مستقبل IR كما تم اختباره سابقًا: `OUT`/`SIGNAL` إلى `A1`، و`VCC` إلى `5V` إذا كانت الوحدة تدعم 5V، و`GND` إلى `GND`. افصل تغذية المحركات والدرايفر أثناء الاختبار.

## أوامر VS Code بالترتيب

افتح Terminal من VS Code داخل المجلد الذي يحتوي `platformio.ini`.

### 1. البناء دون رفع

```bash
pio run
```

انتظر ظهور `SUCCESS`. هذا الأمر يفحص ويجمع البرنامج فقط، ولا يرفعه إلى Arduino.

### 2. رفع اختبار الريموت إلى COM8

```bash
pio run -t upload
```

هذا يرفع Sketch الاختبار إلى Arduino Uno عبر `COM8`، ويستبدل مؤقتًا Firmware الروبوت الموجود على اللوحة. لا تفتح Serial Monitor أثناء الرفع؛ إذا كان مفتوحًا فأغلقه أولًا.

### 3. فتح Serial والضغط على الأزرار

بعد نجاح الرفع، افتح Serial Monitor بهذا الأمر:

```bash
pio device monitor -p COM8 -b 115200
```

اترك المراقب مفتوحًا، ثم اضغط كل زر تريد التحقق منه مرة واحدة. ينبغي أن يظهر سطر مثل هذا عند ضغط زر POWER:

```text
IR;protocol=NEC;address=0x00;command=0x1C;raw=0xE31CFF00;bits=32;button=POWER;map_status=LEARNED
```

ستظهر أسهم الاتجاهات بأسماء `UP` و`DOWN` و`LEFT` و`RIGHT`، والزر الأوسط `OK`، والأرقام مثل `DIGIT_1`، وبقية الأزرار بأسمائها في الخريطة. كل زر من الـ45 له رمز فريد في البيانات المسجلة.

**لا تشغّل سكربت Python على COM8 بينما Serial Monitor مفتوح**؛ لا يستطيع البرنامجان استخدام المنفذ في الوقت نفسه. لا تحتاج إلى الضغط على **Run/F5** في VS Code؛ استخدم أوامر `pio run` و`pio run -t upload` ثم افتح Serial كما أعلاه.

### ملاحظة حول النسخة المصححة والملفات المستبعدة

النسخة المصححة من `src/main.cpp` تحتوي مسارًا احتياطيًا إذا لم يجد مترجم سطح المكتب `Arduino.h`؛ ذلك المسار ينشئ `main()` مكتبيًا فارغًا ينتهي فورًا ولا يستقبل IR. لذلك **لا تشغّل `main.exe` ولا تعتبره برنامج Arduino**؛ اختبار العتاد هو البناء والرفع بواسطة PlatformIO. لم تُضمّن الحزمة المنشورة `main.exe` أو مجلد `.pio` أو إعدادات VS Code المولدة ذات المسارات المطلقة، لأنها ملفات جهاز/بناء محلية وليست ملفات مصدر قابلة للنقل.

بالمقارنة مع الأرشيف السابق، التغيير البرمجي الفعلي في النسخة المرسلة هو `src/main.cpp`؛ ملفات CSV وJSON و`sg555_keymap.h` وسجل الالتقاط بقيت بالقيم نفسها، ولم أستبدل خريطتك المقاسة بتخمينات.

## ماذا لو لم يظهر الاسم؟

- إذا ظهر `button=UNMAPPED` أو `map_status=PROTOCOL_NOT_DECODED`، انسخ السطر كاملًا. لا تعِد المعايرة مباشرة؛ قارن الرمز مع الملف `data/sg555_button_map.csv`.
- إذا لم يظهر أي سطر عند الضغط، تأكد أن مستقبل IR موصول إلى `A1`، وأنه موجّه نحو الريموت، وأن COM8 هو منفذ Arduino في Device Manager.
- إذا كانت الخطوط الحمراء تحت `#include` في المحرر فقط، نفّذ `pio run` وانتظر تنزيل المكتبات، ثم من `Ctrl+Shift+P` اختر **PlatformIO: Rebuild C/C++ Index**. نجاح البناء هو المؤشر الأهم؛ لا تحذف أسطر `#include`.
- إذا ظهر خطأ بناء فعلي في Terminal بدل `SUCCESS`، أرسل نص أول خطأ `error:` كاملًا.

## الملفات التي تحتوي خريطة الأزرار المكتشفة

- `include/sg555_keymap.h` — خريطة C++ الفعّالة التي يستخدمها Sketch، وبها 45 رمزًا متعلّمًا.
- `data/sg555_button_map.csv` و`data/sg555_button_map.json` — النتائج المنظمة لكل زر: البروتوكول والعنوان والأمر والرمز الخام.
- `data/learning_transcript.txt` — سجل جلسة الضغطات التي اكتملت بنجاح.
- `docs/IR_BUTTON_MAP.csv` — نسخة جدول مرجعي للخريطة المكتشفة.
- `docs/SG555_BUTTON_INVENTORY.csv` — الأزرار الـ45 مع قيم NEC المسجلة لكل زر.

تم التحقق من أن CSV وJSON وسجل الالتقاط وخريطة C++ تتطابق في جميع الأزرار الـ45، وأنه لا توجد رموز مكررة أو أزرار متخطاة في الجلسة المحفوظة. لا تستخدم `scripts/learn_buttons.py` لمجرد الاختبار؛ الخريطة موجودة مسبقًا. هذا السكربت اختياري فقط إذا أردت لاحقًا إعادة تسجيل الأزرار.

## بعد انتهاء الاختبار

أغلق Serial Monitor، ثم أعد رفع Firmware المشروع الرئيسي إلى Arduino كي تعود وظائف الروبوت. ملف الاختبار الحالي مستقل ولا يغيّر Firmware المشروع عند تشغيله.

تفاصيل طريقة التسجيل ومصادر الملفات موجودة في [توثيق التقاط أزرار الريموت](../../docs/IR_REMOTE_CAPTURE_AR.md). شاشة اللوحة الأمامية لم تُفعّل بعد؛ راجع ملاحظة الوسوم الظاهرة أدناه والتوثيق قبل أي توصيل.


### القراءة الحالية للوحة الشاشة الأمامية

في الصورة المكبرة تظهر التسميات `IR`, `CLK`, `5V1`, `GND`, `ADD`. رقم الشريحة `U3` غير مقروء؛ و`ADD` **ليس مؤكدًا** أنه خط بيانات `DAT`. لا توصل أو ترفع كودًا للشاشة قبل التحقق من رقم المتحكم ووظيفة هذا الطرف؛ التفاصيل والمصادر في توثيق المشروع المرتبط أعلاه.
